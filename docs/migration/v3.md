# Migrating to v3

v3 changes how the Temporal fallback is loaded. Date parsing, formatting,
constructors, time-zone policies, and plugin APIs keep their existing behavior.
Node 22, 24, and 26 remain supported; Temporal need not be native in the runtime.

## Default ESM Entry

```ts
import atemporal from 'atemporal';
import relativeTime from 'atemporal/plugins/relativeTime';

atemporal.extend(relativeTime);
const date = atemporal('2026-07-15T10:00:00Z');
```

The ESM graph requires ES2022 and top-level await. Module initialization waits
for the fallback only when a complete global Temporal implementation is absent.
All date methods remain synchronous once the import completes. No separate
initialization call is needed. A fallback import failure rejects module loading.

Browser builds should enable code splitting to put the polyfill in a separate
chunk. Runtimes with native Temporal then avoid requesting that chunk. A
single-file build can still contain the polyfill bytes; conditional execution
alone does not reduce its download size. The package keeps the polyfill as a
regular dependency to guarantee fallback availability.

## CommonJS

```js
const { default: atemporal } = require('atemporal');
```

CommonJS remains synchronous. The polyfill is required only when Temporal is
unavailable. A native runtime does not resolve or load the polyfill package.
Prefer the package's `require` export over requiring its ESM file directly:
Node cannot synchronously require an ESM graph containing top-level await.

## Keep ES2020 or IIFE Builds

If your bundler targets ES2020, emits IIFE, or cannot process top-level await,
switch the factory and plugin imports together:

```ts
import atemporal from 'atemporal/compat';
import relativeTime from 'atemporal/compat/plugins/relativeTime';

atemporal.extend(relativeTime);
```

This distribution preserves synchronous initialization and the static polyfill
fallback used in v2. It still selects native Temporal for operations when
available, but its polyfill import remains part of the static dependency graph.
For a bundler error mentioning top-level await, use this entry or adopt an
ES2022 ESM build. Do not force the bundler to claim unsupported syntax is safe.

## Native Deployments

```ts
import atemporal from 'atemporal/native';
import relativeTime from 'atemporal/native/plugins/relativeTime';

atemporal.extend(relativeTime);
```

This ES2020 distribution excludes the fallback entirely and throws at import
time if global Temporal is missing or incomplete.

## Plugins and Types

All eight plugins and `lazyLoad()` work in every distribution. Keep each
factory and its plugins in the same entry family to share runtime, caches,
and plugin state. Leave `globalThis.Temporal` unchanged after initialization.

Temporal declarations are included in the package and support TypeScript 5.4+.
Consumers do not need the polyfill's declarations or native global Temporal
types. There is no runtime Temporal export from the root; raw values remain
available from the explicit constructors and `.raw`.

## Formatting Diagnostics

Formatting still shares its result cache, compilation cache, and counters with
public diagnostics and prewarming. The previous token pool was prewarmed but
never supplied tokens to the formatter. v3 removes that allocation and keeps
`getFormattingMetrics().tokenPoolStats` fields as deprecated zero-valued counters
for compatibility. `prewarm()` continues to compile common and requested formats.

## Release Validation

`pnpm run check:loading` checks native and fallback imports, CommonJS, plugins,
and initial versus total browser payloads. `pnpm run check:native` also compiles
isolated type consumers without installed polyfill packages. The packed artifact
contracts and Vite, Webpack, and Next.js fixtures verify the distributed package.
